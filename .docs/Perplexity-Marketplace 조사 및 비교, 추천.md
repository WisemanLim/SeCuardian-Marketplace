# mcp server marketplace 조사 및 비교, 추천해 주세요.

MCP 서버 마켓플레이스는 “어디서 어떤 MCP 서버를 찾고, 어떻게 설치·운영·과금까지 할 것인가”를 결정하는 선택지들입니다. 실사용 관점(보안·설치 UX·과금·생태계 규모)으로 보면, 현재는 MCP Marketplace(mcp-marketplace.io 계열)와 mcp.so 계열 + 기타 레지스트리(Glama, PulseMCP 등)를 중심으로 보는 것이 현실적입니다.[^1_1][^1_2][^1_3]

아래에서는

1) MCP 서버 마켓플레이스/디렉터리 판을 구조적으로 정리하고
2) 대표 플랫폼별 비교
3) 사용 목적별 추천(개인 개발, 상용 서비스, 데이터/인프라 연동)
을 드리겠습니다.

## MCP 마켓플레이스 전체 그림

MCP(Model Context Protocol) 생태계에서 “마켓플레이스/디렉터리”는 다음 역할을 합니다.[^1_4][^1_3]

- MCP 서버 검색/발견: 카테고리·키워드 기반으로 서버를 검색, 기능·지원 클라이언트·보안 수준을 확인할 수 있습니다.[^1_2][^1_5]
- 설치 및 설정 지원: Claude Desktop, Cursor, VS Code 등 MCP 클라이언트에 바로 설치 가능한 설정(JSON/명령)을 제공합니다.[^1_6][^1_5][^1_2]
- 품질·보안·평판 관리: 자동 보안 스캔, 리뷰·평점, 크리에이터 프로필 등으로 신뢰성을 관리하는 곳이 있고, 깃허브처럼 단순 등록만 제공하는 곳도 있습니다.[^1_3][^1_2][^1_6]

현재(2026년) 기준으로 자주 언급되는 MCP 마켓플레이스/디렉터리는 다음 계열입니다.[^1_1][^1_2][^1_4][^1_3]

- 상업적 마켓플레이스 + 과금/보안 집중: MCP Marketplace, Apify MCP 등.[^1_2]
- 대형 오픈 디렉터리: mcp.so, PulseMCP, Glama, GitHub 레지스트리 등.[^1_3][^1_2]
- 특화형 카탈로그: MCP Market(mcpmarket.com), Fastio MCP Server Marketplace, 각 클라우드/플랫폼 내 MCP 카탈로그(Databricks Marketplace MCP 등).[^1_7][^1_5][^1_8][^1_9][^1_4]

## MCP Marketplace(mcp-marketplace.io) 상세

MCP Marketplace는 “상업적 MCP 서버 마켓플레이스”로서 개발자/크리에이터와 기업 둘 모두를 대상으로 한 플랫폼입니다.[^1_6][^1_2]

- 기능적 특징
    - 유료 MCP 서버 리스트를 공식 지원, 유료·무료·구독·1회 결제 등 다양한 과금 모델 지원.[^1_2]
    - Stripe Connect로 결제 및 정산을 처리, 크리에이터는 매출의 85%를 가져가고 마켓은 15% 수수료 구조.[^1_2]
    - 라이선스 키 인프라(키 발급·검증 SDK)를 내장하여 라이선스 기반 접근 제어를 구성 가능.[^1_2]
- 개발자·운영 관점
    - 자동 보안 스캔을 통해 서버를 등록하면 스캔 결과(보안 점수, 크리티컬 취약점 여부)를 공개해 설치 전 위험 수준을 평가할 수 있습니다.[^1_6][^1_2]
    - “search_servers / compare / creator_profile / recently_added / list_categories” 등의 API 스타일 MCP 도구를 서버로 제공하여, Claude나 Cursor 등에서 대화 내에서 MCP 서버를 검색·비교·설치까지 진행할 수 있게 합니다.[^1_6]
    - 클라이언트 호환성은 MCP-aware 클라이언트 전반(Claude Desktop, Claude Code, Cursor, Codex 등)을 표방합니다.[^1_6]
- 추천 포인트
    - 유료 MCP 서버를 직접 판매하거나, 내부 MCP를 B2B/파트너에게 라이선스로 제공하려는 경우 가장 자연스러운 선택지입니다.[^1_2]
    - 보안 스코어와 리뷰 시스템을 활용해 엔터프라이즈/규제 산업에서 “신뢰 가능한 서드파티 MCP”를 도입하기 위한 평가 지표로 사용할 수 있습니다.[^1_6][^1_2]

## mcp.so 및 기타 오픈 디렉터리

mcp.so는 “목록 수가 가장 많은 오픈 MCP 디렉터리”로 알려져 있으며, 주로 OSS MCP 서버의 카탈로그 역할을 합니다.[^1_2]

- 특징
    - 수천 개 이상 MCP 서버가 등록되어 있어, 새로운 아이디어나 특정 도메인(게임엔진, 데이터베이스, SaaS 툴 등)의 MCP 서버를 탐색하기 좋습니다.[^1_5][^1_2]
    - 대부분 깃허브 연동으로 구현되어 있어, 리포지토리 중심으로 설치 가이드·코드 확인이 가능합니다.[^1_3][^1_2]
    - 보안 스캔이나 과금 인프라는 없고, “레지스트리/카탈로그”에 가깝습니다.[^1_3][^1_2]

Glama, PulseMCP, GitHub Registry 등도 유사하게 “디렉터리/레지스트리”로서 MCP 서버를 나열·검색하는 역할을 합니다.[^1_3][^1_2]

- 장점
    - 완전 무료, 등록 속도가 빠르고 커뮤니티 활성이 좋아서 새로운 MCP 서버를 발굴하는 데 효율적입니다.[^1_3][^1_2]
    - 특정 벤더에 묶이지 않고 OSS 중심 MCP 서버를 운영하려는 경우, 레지스트리로 활용하기 좋습니다.[^1_4][^1_3]
- 한계
    - 별도의 보안 검증·평가 데이터가 부족해, 규제 환경(금융·헬스케어)에서 바로 도입하기에는 내부 보안 검증 프로세스를 추가로 설계해야 합니다.[^1_3]
    - 마켓 기능(유료 판매, 라이선스 키, 분석 대시보드 등)이 없어 비즈니스 모델을 얹으려면 별도 빌드가 필요합니다.[^1_2][^1_3]

## MCP Market (mcpmarket.com)과 “추천 MCP 서버” 카탈로그

MCP Market(mcpmarket.com)은 한글 페이지를 포함해 “추천 MCP 서버 목록”과 “인기 MCP 서버 일간 랭킹”을 제공하는 큐레이션 성격의 사이트입니다.[^1_8][^1_9]

- 특징
    - Claude, Cursor를 Figma, Databricks, Storybook, Ghidra 등 다양한 도구에 연결하는 MCP 서버를 큐레이션 형태로 소개.[^1_8]
    - “추천 MCP 서버” 섹션과 날짜별 “인기 MCP 서버 목록”을 통해 어느 정도 커뮤니티/사용자 지표가 반영된 서버를 간접적으로 볼 수 있습니다.[^1_9][^1_8]
    - 서버별로 기능 요약과 설치·연동 포인트를 한국어 설명으로 소개하는 케이스도 있어, 국내 개발자에게 접근성이 좋습니다.[^1_9][^1_8]
- 활용 방안
    - MCP 초입 단계에서 “어떤 MCP 서버가 실무에서 의미 있는지” 감을 잡는 데 유용합니다.[^1_8][^1_9]
    - 특정 도메인(예: Ghidra 역공학, Unity/Godot 게임엔진, Jira 자동화, Home Assistant 등)의 대표 MCP 서버를 빠르게 파악할 수 있습니다.[^1_9][^1_8]

## 기타: 클라우드·플랫폼 내 MCP 카탈로그

Databricks Marketplace, AWS Marketplace, 기타 SaaS 벤더들도 자체적으로 MCP 서버/커넥터를 마켓플레이스로 노출하기 시작했습니다.[^1_10][^1_7][^1_4]

- Databricks Marketplace의 MCP 서버: Databricks가 제공하는 데이터·노트북·워크플로우를 MCP 서버로 외부 에이전트가 호출할 수 있게 하는 구성이 검증되고 있습니다.[^1_7]
- AWS Marketplace MCP 서버 문서: AWS는 Marketplace 내 MCP 서버 지원 문서를 통해 AI 에이전트와 AWS 서비스 간 통합을 설명하고 있습니다.[^1_10]
- 이런 벤더 별 마켓플레이스는 “그 벤더의 리소스를 MCP로 노출”하기 위한 특화 채널로 보는 것이 타당합니다.[^1_4][^1_10][^1_7]

엔터프라이즈 환경에서는, “공용 MCP 마켓플레이스(MCP Marketplace 등)”와 “특정 클라우드 내 MCP 카탈로그(Databricks, AWS 등)”를 병행 사용하게 될 가능성이 큽니다.[^1_7][^1_4][^1_2]

## 목적별 추천 시나리오

Wiseman 님 관점에서, 몇 가지 대표적인 요구 시나리오에 따라 선택을 구분해 보겠습니다.

### 1. 개인 개발자/팀: 다양한 MCP 서버 탐색·실험

목적: 새로운 MCP 서버를 탐색해 PoC, 사이드 프로젝트, 사내 데모 등에 활용.

- 1차 카탈로그: mcp.so + Glama + PulseMCP
    - 이유: 등록 수가 많고, OSS 중심이어서 실험용 서버를 쉽게 찾고 소스 코드까지 바로 확인 가능.[^1_5][^1_3][^1_2]
- 큐레이션 참고: MCP Market 추천/인기 목록
    - 이유: 필터링된 “실제로 유용한” MCP 서버를 빠르게 파악할 수 있음.[^1_8][^1_9]

이 경우에는 비용·보안보다 “폭넓은 탐색”과 “코드 레벨 튜닝”이 중요하므로 상업 마켓(결제/보안)보다는 오픈 디렉터리 조합이 효율적입니다.[^1_8][^1_3][^1_2]

### 2. 상용 제품/서비스에 MCP 서버를 패키징·판매

목적: 직접 만든 MCP 서버를 외부 고객에게 유료로 제공하거나, 파트너용 MCP 서버를 운영.

- 주력 선택: MCP Marketplace
    - Stripe Connect 기반 결제·정산, 85/15 수익 분배, 라이선스 키 인프라, 구독/1회 구매, 무료+Pro 티어 등의 상업 기능을 이미 제공.[^1_2]
    - 자동 보안 스캔과 공개 리포트를 통해 엔터프라이즈 고객에게 “제3자 검증” 역할을 제공할 수 있음.[^1_6][^1_2]
- 보조: Apify MCP 등 유사 상업 플랫폼(과금+호스팅)
    - Apify MCP는 MCP 기반 데이터·자동화 서비스를 Apify 마켓플레이스와 연계하는 모델을 지원하는 것으로 정리되며, 80/20 수익 분배 구조를 갖습니다.[^1_2]

Wiseman 님이 향후 “전략적 피벗”으로 MCP 기반 B2B/B2D 서비스를 고려하신다면, MCP Marketplace를 우선 대상 플랫폼으로 연구·파일럿하는 것이 합리적으로 보입니다.[^1_6][^1_2]

### 3. 엔터프라이즈/규제 산업(금융·헬스케어) 환경에서 MCP 서버 도입

목적: 사내 MCP 서버 + 서드파티 MCP 서버 조합으로 AI 에이전트 인프라를 구성, 규제·보안·컴플라이언스 요구사항을 만족.

- 서드파티 채널
    - MCP Marketplace: 자동 보안 스캔, 공개된 취약점 정보, 리뷰·평판 데이터를 기반으로 도입 검토.[^1_6][^1_2]
    - Anthropic Connectors: Claude 기반 워크로드에서 벤더 공식 커넥터를 사용해 최소한의 신뢰 레벨 확보.[^1_3][^1_2]
- 사내 레지스트리
    - OSS 디렉터리(mcp.so 등)의 소스를 fork/복제하여 내부 GitLab/Artifact Registry에 재구성하고, 사내 MCP 디렉터리(내부 포털)를 구축하는 패턴.[^1_4][^1_3]
    - Databricks Marketplace·AWS Marketplace MCP 카탈로그 등 기존 클라우드 마켓을 통해 내부 데이터·서비스를 MCP로 노출.[^1_10][^1_7]

Wiseman 님의 데이터 프라이버시/규제 컴플라이언스 배경을 고려하면, “MCP Marketplace의 보안 스코어＋사내 보안 평가 지표”를 결합해 MCP 서버 도입 표준을 만드는 방향이 적합해 보입니다.[^1_4][^1_6][^1_2]

## MCP 서버 마켓플레이스 선택 가이드(요약 기준)

마지막으로, 마켓플레이스 선택 시 고려할 핵심 기준을 정리하면 다음과 같습니다.[^1_5][^1_8][^1_3][^1_2]

- 보안·신뢰
    - 자동 보안 스캔 여부, 스캔 결과가 공개되는지, 리뷰·평점 시스템 존재 여부.[^1_3][^1_6][^1_2]
- 과금·비즈니스 모델
    - 유료 서버 지원 여부, 수익 배분 구조(예: 85/15 vs 80/20), 구독/1회 결제/무료+Pro 티어 지원 여부.[^1_2]
- 설치 경험
    - MCP 클라이언트 내 원클릭 설치 가능 여부, 설치·설정 JSON을 얼마나 자동으로 제공하는지.[^1_5][^1_6][^1_2]
- 생태계 규모·큐레이션
    - 서버 수, 카테고리 다양성, 한국어 문서/설명 유무, 인기·추천 서버 랭킹 지원 여부.[^1_9][^1_5][^1_8][^1_2]
- 클라이언트·플랫폼 호환
    - Claude, Cursor, VS Code, Databricks, AWS 등 어떤 클라이언트/플랫폼과 자연스럽게 연계되는지.[^1_10][^1_7][^1_6][^1_2]

Wiseman 님이 목표로 하는 “전략적 피벗”의 방향(예: B2B 제품 vs 내부 엔터프라이즈 플랫폼 vs 교육/컨설팅 도구)에 따라, MCP Marketplace를 중심에 두고 오픈 디렉터리와 벤더별 MCP 카탈로그를 어떻게 조합할지 설계하는 게 합리적으로 보입니다.[^1_4][^1_5][^1_8][^1_2]

마켓플레이스를 선택할 때, 가장 중요한 것은 “향후에 어떤 비즈니스 모델을 얹을 것인지”인데요. 지금 생각하고 계신 MCP 활용 방향이 개인 개발자 중심인지, 상용 서비스/제품 중심인지, 아니면 엔터프라이즈 플랫폼 중심인지 중에서 어느 쪽에 더 가깝다고 보시나요?

# 기업내에서 사용할 Agent를 관리한 마켓플레이스를 구축하고자 할 때 참고할만한 MCP Server Marketplace를 추천한다면?

기업 내에서 사용할 에이전트를 관리하는 “사내 MCP 기반 에이전트 마켓플레이스”를 구축한다면, 외부 상업 마켓을 그대로 쓰기보다는 **MCP Marketplace(mcp-marketplace.io) + mcpservers.org 디렉터리 + MCP Market(mcpmarket.com)의 설계 패턴을 참고해 내부 전용으로 재구성하는 방향**을 추천할 수 있습니다.[^2_1][^2_2][^2_3][^2_4]

2) 참고할 외부 MCP Server Marketplace/디렉터리
3) 엔터프라이즈 아키텍처 관점에서의 설계 포인트
를 정리해보겠습니다.

## 기업 내 에이전트 마켓플레이스에 필요한 기능

엔터프라이즈용 “에이전트 마켓플레이스”는 MCP 서버를 에이전트의 표준 도구로 관리하는 포털/레지스트리라고 볼 수 있습니다.[^2_5][^2_6]

- 카탈로그/디렉터리 기능
    - 에이전트·MCP 서버 목록, 카테고리(업무 도메인, 시스템 도메인, 위험 등급)별 탐색, 태그 기반 검색.[^2_2][^2_3][^2_4]
    - 각 MCP 서버/에이전트의 메타데이터(버전, 담당 조직, API 스펙, 권한 요구사항, 로그/모니터링 위치 등)를 관리.[^2_3][^2_5]
- 설치·연결 관리
    - Claude Desktop, Cursor, 사내 Agent Host 등 다양한 클라이언트에서 바로 설정 파일을 가져다 쓸 수 있는 설치/연결 템플릿 제공.[^2_7][^2_3]
    - 환경별(개발/스테이징/운영) MCP 서버 엔드포인트 및 인증 방식(사내 OAuth, mTLS, Key 관리)을 일관되게 노출.[^2_6][^2_5]
- 보안·컴플라이언스·거버넌스
    - MCP 서버별 데이터 분류(개인정보, 금융정보 등급), 접근 통제 정책, 감사 로그 경로, 위험 평가 결과를 메타데이터로 관리.[^2_8][^2_5][^2_6]
    - 보안 스캔·취약점 점검 결과를 레벨/스코어로 정리해, 에이전트가 사용할 MCP 서버를 승인·차단하는 기준으로 활용.[^2_9][^2_5][^2_8]
- 운영·모니터링
    - 에이전트·MCP 서버별 호출량, 에러율, 평균/최대 응답시간, 비용(내부 자원 사용량 또는 외부 API 과금)을 대시보드화.[^2_10][^2_5][^2_6]
    - 에이전트 버전/배포 이력과 MCP 서버 버전/변경 내역을 연결해 “어떤 에이전트가 어떤 MCP 버전에 의존하는지”를 추적.[^2_5][^2_6]

## 외부에서 참고할 MCP Server Marketplace/디렉터리

사내 마켓플레이스를 설계할 때 참고하기 좋은 외부 사례들을 몇 가지로 정리하면 다음과 같습니다.

### 1. MCP Marketplace (상업 마켓의 전체 흐름 참고)

MCP Marketplace(mcp-marketplace.io 계열)는 상업적 MCP 서버 마켓플레이스로, MCP 서버 카탈로그·보안 스캔·결제·라이선스 관리까지 통합합니다.[^2_10][^2_3]

- 참고할 부분
    - MCP 서버 카탈로그 구조: 카테고리, 태그, 상세 설명, 설치 방법, 지원 클라이언트, 보안·신뢰 지표 등을 한 화면에서 제공하는 구조.[^2_3]
    - 서버 등록 플로우: MCP 서버를 등록하면 메타데이터 검증 및(외부 마켓 기준으로) 보안 스캔/리뷰를 거쳐 공개하는 일련의 파이프라인.[^2_10][^2_3]
    - 수익화 모델은 사내에서는 불필요하지만, “플랜/티어” 개념을 사내에서는 권한·조직·환경별 액세스 레벨로 변형해 적용할 수 있습니다.[^2_10]

Wiseman 님이 기업 내에서 에이전트 도입 거버넌스를 설계할 때, MCP Marketplace의 “등록→검증→공개→설치” 흐름을 사내용 체크리스트로 재구성하는 것이 유용합니다.[^2_3][^2_10]

### 2. Awesome MCP Servers / mcpservers.org (디렉터리 정보 구조 참고)

mcpservers.org는 “Awesome MCP Servers” 디렉터리로, 다양한 MCP 서버를 카테고리·제품·설명 테이블로 정리한 위키 스타일 구조를 제공합니다.[^2_11][^2_4][^2_3]

- 참고할 부분
    - 카테고리(데이터베이스, 스크래핑, 서버 호스팅, 생산성 등)별 목록 구조와, 각 MCP 서버에 대해 “제품명, 운영사, 주요 기능”을 간단히 표로 정리하는 패턴.[^2_4][^2_3]
    - “Connection Management” 카테고리에서 Toolbase 같은 플랫폼이 여러 MCP 서비스 간 연결을 관리한다는 식의 메타 구조는, 사내에서도 “연결 관리형 에이전트” 등을 정의할 때 참고 가능.[^2_3]

사내 마켓에서는 기능적 카테고리(예: CRM, ERP, 로그 분석, 배치 오케스트레이션 등)로 MCP 서버와 에이전트를 분류할 수 있는데, mcpservers.org의 심플한 카테고리/테이블 방식을 베이스로 삼아 내부 도메인에 맞게 확장하는 접근을 권장합니다.[^2_4][^2_3]

### 3. MCP Market (mcpmarket.com) – 큐레이션·추천 구조 참고

MCP Market은 MCP 서버를 카테고리·큐레이션·인기 목록 형태로 보여주는 사이트로, 카테고리별 MCP 서버 컬렉션을 제공하고 있습니다.[^2_12][^2_13][^2_2]

- 참고할 부분
    - 카테고리 페이지 구조: 예를 들어 “Cloud Infrastructure” 카테고리에는 1,263개 MCP 서버가 큐레이션되어 있고, 각 서버에 짧은 설명과 링크를 제공.[^2_12]
    - “E-commerce Solutions” 같은 업무 도메인 중심 카테고리 설계: 도메인별 MCP 서버 컬렉션을 제공하는 방식은 사내에서도 업무 라인(영업, 마케팅, 운영 등)별 에이전트 컬렉션을 만드는 데 유용.[^2_13][^2_2]

사내 마켓플레이스에서는, 단순히 기술 카테고리뿐 아니라 “업무 프로세스 카테고리(예: 계약 심사, 청구·수납, 고객 문의 대응)”로 MCP 에이전트를 큐레이션하는 것이 중요하고, MCP Market의 도메인 기반 카테고리 구조를 그대로 차용할 수 있습니다.[^2_13][^2_2][^2_12]

## 엔터프라이즈 에이전트 마켓플레이스 아키텍처 관점

Wiseman 님 입장에서 아키텍처·거버넌스 측면으로 볼 때 핵심은 “에이전트/MCP 서버를 API/서비스처럼 관리하는 내부 플랫폼”입니다.[^2_6][^2_8][^2_5]

### 아키텍처 레이어

- MCP 서버 레지스트리 레이어
    - 사내 MCP 서버와 선정된 외부 MCP 서버를 모두 “서비스 카탈로그” 형태로 관리.[^2_5][^2_3]
    - 각 엔트리에는 MCP 스펙(schema, tools, resources), 인증 스킴, 대상 시스템(내부 DB, SaaS, 레거시 등)을 포함.[^2_6][^2_5]
- 에이전트 정의/버전 관리 레이어
    - 에이전트가 사용하는 MCP 서버들의 목록(도구 그래프)을 의존성으로 명시하고, 버전별로 저장.[^2_5][^2_6]
    - 에이전트가 변경될 때 MCP 서버 버전 호환성 체크 및·배포 파이프라인 연계.[^2_6][^2_5]
- 거버넌스·보안·컴플라이언스 레이어
    - MCP 서버 등록 시, 데이터 프라이버시/보안 체크리스트(PII 포함 여부, 데이터 위치, 암호화, 로깅 정책 등)를 통과해야 “프로덕션용”으로 승격.[^2_8][^2_5][^2_6]
    - 에이전트 마켓플레이스 UI에서는 각 에이전트·MCP 서버에 대해 위험 등급·승인 상태(개발/승인 대기/운영)를 표시.[^2_8]
- 관측·운영 레이어
    - 호출 로그를 중앙 수집(예: OpenTelemetry+SIEM), MCP 서버별·에이전트별 대시보드로 시각화.[^2_5][^2_6]
    - 비정상 패턴(대량 호출, 민감 테이블 쿼리 증가 등)을 탐지하면 에이전트 또는 MCP 서버를 임시 차단하는 제어 플로우.[^2_8][^2_6]


### 외부 마켓 활용 방식

사내 마켓플레이스를 완전히 폐쇄적으로 만들기보다는, **외부 MCP 디렉터리/마켓에서 검증된 MCP 서버를 소스·참고용으로 가져오는 패턴**을 추천합니다.[^2_11][^2_4][^2_3]

- mcpservers.org / MCP Market에서 OSS MCP 서버를 선정 → 사내 GitLab/레포로 포크 → 내부 보안·데이터 정책에 맞게 수정 → 사내 마켓플레이스에 등록.[^2_11][^2_4][^2_3]
- 상업 마켓(MCP Marketplace 등)에서 보안·품질이 검증된 MCP 서버를 선정하되, 데이터 프라이버시 요구사항에 따라 “사내 프록시 MCP 서버”로 래핑하여 도입.[^2_10][^2_8][^2_5]

이렇게 하면 외부 생태계의 혁신을 활용하면서도, 데이터 프라이버시·컴플라이언스 측면에서 통제 가능한 구조를 가져갈 수 있습니다.[^2_6][^2_8][^2_5]

## Wiseman 님에게 맞는 추천 방향

정리하면, 기업 내 에이전트 마켓플레이스를 설계할 때 참고할 MCP 서버 마켓/디렉터리로는 다음 조합을 권장드립니다.

- **설계 흐름·거버넌스 관점**: MCP Marketplace – “등록→검증→공개→설치” 플로우와 보안·플랜 모델을 내부 거버넌스로 재해석.[^2_3][^2_10]
- **카탈로그/정보 구조 관점**: mcpservers.org(Awesome MCP Servers) – 카테고리·제품·설명 테이블 기반의 심플한 디렉터리 구조.[^2_4][^2_11][^2_3]
- **도메인 큐레이션 관점**: MCP Market(mcpmarket.com) – 도메인별 카테고리 페이지·큐레이션·인기 목록 구조.[^2_2][^2_12][^2_13]
